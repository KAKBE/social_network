Любое изменение критерия после испытания оформляется отдельным коммитом с пометкой «изменение критерия» и не отменяет исходную версию.

## Считаем

На бесплатной связке без договора с поставщиком карт — подложка OpenStreetMap в Leaflet, геокодирование через публичный Nominatim, обращения к которому идут через Backend API, — можно реализовать основной сценарий «найти на карте место, которое рекомендовал знакомый» в браузере смартфона.

## Почему это опасно

- Поставщик карт не выбран (ответ команды 15.10.2026), а на карте держатся все три сценария питча (Последам-1-12.pdf, слайд 6).
- Этап RAT-PoC в питче прямо назван «изучаем вопрос по картам» (слайд 9).
- В принятой C4 (Diagrams.pdf, стр. 2) Backend API обращается к картографическому провайдеру за картой, геокодированием и поиском мест. Если связка не работает, придётся менять поставщика, бюджет и, возможно, архитектуру до начала MVP.

## Критерий успеха

Допущение подтверждено, только если выполнены **все четыре** пункта.

| № | Что проверяем | Порог | Как считаем |
|---|---|---|---|
| К1 | Точность геокодирования адресов Москвы | не меньше 27 из 30 адресов (90%) | расстояние между координатами **первого** результата Nominatim и эталоном не больше 100 м; адрес без результата считается провалом |
| К2 | Скорость открытия карты с местами друзей на смартфоне | не больше 2,0 с минимум в 19 из 20 повторных открытий | от начала загрузки страницы до отрисовки всех меток; 50 мест друзей; кэш браузера прогрет одним открытием до серии |
| К3 | Корректность доступа | 100% рекомендаций друзей видны, 0 рекомендаций посторонних видны | автоматический тест на тестовых данных |
| К4 | Соблюдение условий поставщиков | все пункты выполнены | без ключа и оплаты; не больше 1 запроса в секунду к Nominatim; свой User-Agent; кэш результатов; нет поиска по мере ввода; атрибуция «© OpenStreetMap contributors» видна на карте |

Первая загрузка «с нуля» (пустой кэш) записывается отдельно, для сведения, без порога.

## Проверяем так

1. **К1.** Команда до запуска скрипта вручную снимает эталонные координаты каждого адреса из списка ниже в 2ГИС — источнике, независимом и от Nominatim, и от альтернативного геокодера Яндекса: вводит адрес как есть, берёт координаты точки, которую показал поиск, записывает их в `checks/addresses.csv` и делает коммит. Затем скрипт `checks/geocode_check.py` один раз прогоняет 30 адресов через тот же адаптер, что использует Backend: один поток, 1 запрос в секунду, ответы сохраняются в файл и повторно не запрашиваются. Учитывается только первый результат — проверяющий не выбирает вариант вручную. Скрипт считает расстояния и число попаданий.
2. **К2.** Команда открывает образец на смартфоне, делает одно открытие для прогрева кэша, затем 20 открытий подряд. Время на каждом открытии показывает сам образец (метка производительности на экране). Каждое значение записывается в `checks/замеры_скорости.csv`.
3. **К3.** `pytest` в `backend/tests/` на тестовых данных: пользователь, его друзья, посторонние; проверяются ответы ленты и карты.
4. **К4.** Сверка кода и интерфейса с правилами: https://operations.osmfoundation.org/policies/nominatim/ и https://operations.osmfoundation.org/policies/tiles/ (прочитаны 15.10.2026).

### Альтернативный путь: сравнение с геокодером Яндекса (добавлено 15.10.2026, до испытания)

Не меняет К1 и его вердикт. После К1 скрипт `checks/geocode_compare_yandex.py` прогоняет те же 30 адресов через HTTP API Геокодера Яндекса с той же областью поиска (Москва), учитывает первый результат и считает расстояния до того же эталона с тем же порогом 100 м. Ответы Nominatim берутся из сохранённого `checks/geocode_raw.json` и повторно не запрашиваются. Результат: `checks/geocode_compare.csv` — число попаданий и медиана расстояния у обоих геокодеров. Ключ API хранится в `.env` и в репозиторий не попадает.

## Образец и условия

- Образец: Vue + Leaflet (Web Client), FastAPI + SQLAlchemy (Backend API), PostgreSQL в Docker — состав контейнеров по C4 уровня 2.
- Сеть для К2: смартфон и ноутбук в одной Wi‑Fi сети. Это измеряет локальную сеть, а не мобильный интернет 4G.
- Модель смартфона, браузер и сеть записываются в таблицу замеров в момент испытания.

**Что показали промахи** (разбор после испытания, не часть критерия):
- Яндекс промахивается только на 5 крупных территориях — Покровка (корпус 13), Лужники, Зарядье, МГТУ, зоопарк: 124–243 м. Это заранее указанное ограничение набора.
- Nominatim, кроме тех же территорий, находит **другой объект**: адреса с дробью «13/6», «5/1» превращаются в другие дома (Б. Никитская, 58; Театральный проезд, 62) — 383–385 м; для Ленинградского пр., 49 найдена только улица — 3,2 км; вместо ВДНХ — кофейня (702 м), вместо зоопарка — храм (534 м).
- Если бы пользователь выбирал лучший из 5 вариантов Nominatim, попаданий было бы 20 из 30 — выбор из списка проблему не решает.

**Условия Яндекса (прочитаны 15.10.2026, https://yandex.ru/legal/maps_api/).** П. 6.6.1: бесплатный Геокодер можно использовать только вместе с JavaScript API Яндекс Карт; отображать его результаты на картах третьих лиц запрещено. П. 5.1.5: хранить ответы можно не дольше 30 дней. Значит, вариант «Геокодер Яндекса + подложка OSM», намеченный до испытания, по бесплатным условиям недопустим.

## Интерпретация

Допущение «на бесплатной связке без договора можно реализовать сценарий» **в исходной формулировке не подтверждено**: бесплатный геокодер, совместимый с подложкой OSM, ошибается на трети адресов Москвы, в том числе находит другие объекты. При этом сценарий 1 «найти место друга» от геокодера не зависит: точку места задаёт автор рекомендации, карта и доступ работают (К3, К4). Геокодер влияет на добавление места (US-09).

## Ограничения результата

- Эталон — точка первого результата 2ГИС; для больших территорий точка «объекта» у поставщиков различается, что увеличивает число промахов у обоих геокодеров.
- 30 крупных известных объектов; на небольших кафе и коворкингах точность может быть другой.
- Эталон снимал ИИ-ассистент по правилу «первый результат» без ручной проверки каждой точки.
- К4 по подписи проверен в эмуляции экрана на ноутбуке; на реальном смартфоне подпись подтверждается вместе с К2.
- К2 не измерен: вывод о скорости на смартфоне сделать нельзя. Серия на ноутбуке — проверка инструмента, не К2.

## Следующее решение (определено до испытания)

- Все четыре пункта выполнены → связка OSM + Nominatim остаётся для Прототипа и MVP; переход на другого поставщика рассматривается при росте числа пользователей (ограничения Nominatim).
- Провал К1 → прогнать те же 30 адресов через геокодер Яндекса (альтернативный путь) и сравнить; при лучшем результате — отдельный ADR о смене геокодера при сохранении подложки OSM.
- Провал К2 → найти шаг критического пути, где теряется время; пробовать группировку близких меток и ограничение числа мест в ответе; повторить серию.
- Провал К3 → ошибка логики доступа; исправить и повторить тест до любой демонстрации.
- Провал К4 → устранить нарушение до любого публичного использования.

## Принятое решение (15.10.2026, после испытания)

- Сравнение с Яндексом выполнено. Результат лучше, но условия Яндекса запрещают его связку с подложкой OSM — смена геокодера при сохранении подложки невозможна. См. ADR-4 (предложено).
- В образце: адрес — подсказка, точку подтверждает пользователь. После выбора адреса форма предупреждает, что точка может отличаться на сотни метров; нажатие на карту поправляет точку и сохраняет адрес (`AddView.vue`, проверено в браузере ноутбука 15.10).
- До MUP: выбрать геокодер по условиям и цене — полный переход на Яндекс Карты (подложка + геокодер, с учётом хранения ≤ 30 дней) или платный геокодер; повторить К1 на том же наборе и эталоне.
- К2 провести на смартфоне; до этого вывод о скорости не делается.
