## 0. Запуск образца на ноутбуке

Нужны Python (образец проверен на 3.14), Node.js 22+ и запущенный Docker Desktop. Один раз после `git clone`:

```powershell
git clone https://github.com/KAKBE/social_network.git
cd social_network
python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt
cd frontend; npm install; cd ..
```

Запуск (из корня репозитория):

```powershell
docker compose up -d db                                   # PostgreSQL
cd frontend; npm run build; cd ..                         # сборка интерфейса
cd backend; ..\.venv\Scripts\python -m app.seed           # тестовые данные: у lesha ровно 50 мест друзей
..\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 1. К1 — геокодирование (≈ 40 минут)

1. Откройте `checks/addresses.csv` (Excel или VS Code).
2. Для каждого из 30 адресов: вставьте строку адреса **как есть** в поиск Яндекс Карт → нажмите на найденную точку → скопируйте координаты (формат `55.123456, 37.123456`) → запишите в `ref_lat` и `ref_lon`.
   - Если Яндекс предлагает несколько вариантов, берите первый.
   - Не запускайте скрипт и не смотрите на результат Nominatim, пока не заполнены все 30 строк.
3. Сохраните файл в UTF-8 и сделайте коммит:
   `git add checks/addresses.csv; git commit -m "Эталонные координаты К1"`
4. Запустите проверку **один раз**:
   `.venv\Scripts\python checks\geocode_check.py`
   Скрипт сделает 30 запросов, по одному в секунду (около 30 секунд), сохранит ответы в `checks/geocode_raw.json` и результат в `checks/geocode_results.csv`. Повторный запуск берёт сохранённые ответы и Nominatim не нагружает.
5. Закоммитьте `checks/geocode_raw.json` и `checks/geocode_results.csv`.

## 2. К2 — скорость на смартфоне (≈ 15 минут)

1. Телефон и ноутбук — в одной Wi‑Fi сети. На телефоне откройте `http://192.168.3.18:8000` (IP ноутбука в сети «Беспроводная сеть 2» на 15.10; если сеть другая — узнайте IP командой `ipconfig`).
   Если страница не открывается, разрешите порт в брандмауэре Windows (PowerShell от администратора):
   `New-NetFirewallRule -DisplayName "PoSledu 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`
2. Войдите как `lesha`. Проверьте, что на кнопке вверху написано «50 мест · … мс».
3. Нажмите эту кнопку → введите название серии, например `phone-wifi-1` → «Начать».
4. Обновите страницу **21 раз** (потянуть вниз или кнопка обновления браузера), каждый раз дожидаясь меток на карте. Замер №0 — прогрев кэша, он не учитывается.
5. Нажмите кнопку вверху → «Завершить серию».
6. Запишите модель телефона, браузер и его версию, сеть (Wi‑Fi, название), уровень заряда/режим энергосбережения — в раздел «Собранные свидетельства» протокола.
7. На ноутбуке: `.venv\Scripts\python checks\perf_report.py phone-wifi-1`
   Отчёт сохранит все замеры в `checks/замеры_скорости.csv`. Закоммитьте его.

Серия `desktop-localhost-check` в выгрузке — проверка инструмента на ноутбуке 15.10, к К2 не относится.

## Если что-то пошло не так

- Поиск адреса пишет «недоступен» — место можно отметить нажатием на карту; причина записывается в окно сервера (`Geocoder unavailable: ...`). Сохраните это сообщение. На ноутбуке есть сетевой интерфейс `happ-xray` (похоже на VPN или прокси): если он включён, запросы к Nominatim могут идти через него.
- Сбросить тестовые данные: `cd backend; ..\.venv\Scripts\python -m app.seed` (замеры и кэш геокодера сохраняются).
